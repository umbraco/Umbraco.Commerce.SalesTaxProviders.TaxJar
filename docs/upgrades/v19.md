# Upgrade to Umbraco 19

From Umbraco Commerce `[18.0.0, 18.999.999)` (CMS 18) to Umbraco Commerce `19.0.0-beta.1` (CMS `19.0.0-beta1`, tag `release-19.0.0-beta1`).
Branch `v19/topic/cms-19-upgrade` → PR into `release/19.0.0`, cut from `main` (`ee71245`).

**Targets CMS release:** `release-19.0.0-beta1`, via Umbraco Commerce `19.0.0-beta.1` (MyGet `umbracoprereleases`, already in `NuGet.config`). The package's own version is `19.0.0-beta.1`.

The package depends on `Umbraco.Commerce.Core`, `Microsoft.Extensions.Http` and `TaxJar`, never on `Umbraco.Cms.*` directly, so CMS breaking changes reach it only through Commerce. Commerce's own v19 inventory (Core repo, `docs/upgrades/v19.md`) is the source for those. Same pattern as the Stripe provider's v19 upgrade.

## Breaking changes for consumers

- Requires Umbraco Commerce 19 (.NET 11).
- TaxJar 5.0 (was 4.0), bringing RestSharp 114 (was 108): sites that reference TaxJar or RestSharp themselves move with it.
- Behaviour, likely but not verified against RestSharp's source: the provider sets no timeout, and with TaxJar 5 none is put on the request, so RestSharp 114's default timeout (believed to be 100 seconds) now applies where RestSharp 108 had no limit. A TaxJar call that hangs now fails and the provider returns zero tax, as it does for any TaxJar error.

## Follow-ups

- Live smoke with a TaxJar sandbox token before 19.0.0 final: a US→US order in USD gets `amount_to_collect` and the city/county/state/country breakdown (live smoke pending; the unit tests can't run this).
- Confirm RestSharp 114's default timeout and decide whether to pass an explicit one to `TaxjarApi`.
- `TaxjarApiHttpTests` swap TaxjarApi's private `apiClient` field by reflection; recheck on the next TaxJar bump (the tests fail loudly if it's renamed).
- `PaymentInfo.CountryId!.Value` runs outside the `try`, so an order with neither a shipping nor a payment country throws instead of returning zero tax (pre-existing).
- An order line whose `TaxClassId` isn't found gets no product tax code instead of the store default (pre-existing).
- `(int)quantity` truncates fractional quantities; check the sign TaxJar expects for `discount` against Commerce's negative adjustments (pre-existing).
- The breakdown ignores `special_district_tax_collectable`, so the four rows may not add up to `amount_to_collect` (pre-existing).
- `NU1510`: `Microsoft.Extensions.Http` is part of the shared framework (`Microsoft.AspNetCore.App`) and the explicit reference can go (pre-existing on v18).
- Test project package versions (xunit 2.6.6, Test.Sdk 17.8.0, FluentAssertions 6.12.0) copy Stripe's; update the providers together later.
